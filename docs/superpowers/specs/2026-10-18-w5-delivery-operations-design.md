# W5 交付与运营规范

范围为综合报告 C04–C07，以及 W1–W4 的最终集成验收。交付层级固定为研究 / 明确模拟单证 / 测试代币的受控 Injective 测试网应用。直接用户已授权本轮部署、必要交易、测试、提交和推送。授权不构成真实承运人、企业身份、法律权利或生产值班方的证明。

## 运行和停止

- 进程存活、接流量就绪、链确认 / 对账、来源时效和后台积压分别呈现。公开就绪端点只给非敏感结果；详细指标和告警需管理员认证。
- 持久运行目录只允许一个应用进程；租约同时覆盖停机备份和还原。跨主机共享目录无法确认旧进程已死时拒绝抢占。
- 存储写入 / 空间、启动、链观测或关键材料异常时停止新增认购 / 收费 / 发行；读取、对账和既有领取入口保持可达，链本身仍负责最终退出条件。
- 告警按状态变化持久化，可显式配置发送至操作员接收端；本地接收端实测与外部值班人员接收证据分开。

## 容量和恢复目标

单进程研究部署目标：20 个并发 HTTP 客户端，至少 2,000 次混合请求，错误率 <= 1%，p95 <= 1,000 ms；以实际报告记录机器、数据规模和耗时，不据短测声称长期稳定性。账本另测至少 1,000 条事件，重复日志不重复入账。长稳门为连续 10 分钟、每秒至少 1 次就绪与混合业务读取，并记录最大内存、延迟和失败。

仅支持停机一致性快照。备份采用独立 AES-256-GCM 密钥，包含所有 runtime、initialized 标记、配置与文件摘要；密钥不得写入备份。还原至新目录，拒绝覆盖、路径逃逸、符号链接、重复路径、摘要不符、错密钥和缺件；先验证整个包才写入。原运行目录不可用后，独立新进程重开 vault、重算证据、重建账本并核对余额。隔离容器 / 新目录恢复和独立物理机器恢复须准确标注。

RPO 为最后一次已完成停机快照；RTO 目标 <= 5 分钟（本地隔离替代环境）。真实源主机丢失、异地密钥保管和外部人员接管需独立场地 / 人员，不能由同机测试自动关闭。

## 构建、部署和迁移

使用锁文件在干净目录安装、编译两次，比较标准化 artifact、ABI 和前端静态资产摘要。Solidity 保持 0.8.24 / Paris / viaIR / 200 runs；标准 runtime / initcode 大小限制不放宽。运行镜像需包含 W3 加载器校验所需的六份固定 artifact。

新建完整 W3 控制实例，保留所有旧网络实例、资产和持仓。测试角色使用独立生成的研究密钥，由同一操作员保管，不能声称治理成员来自不同真实组织。治理仍需两把不同密钥及链上 3,600 秒等待，禁止时间作弊。每笔广播先落盘精确签名哈希，未知状态只读对账。仅测试币；主网和真实业务关闭。

最终源码、CI 必须任务、镜像、合约 artifact、配置和交易收据相互绑定。历史失败不覆盖。最终验收报告逐项给出 G-LOCAL / G-TESTNET / G-EVIDENCE / G-OPS / G-BUSINESS 适用结果，未满足的外部条件保留。
