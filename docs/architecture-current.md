## 业务和模块

主流程：研究单证 → 签发与持有人同意 → 估值、资格及完整条款 → 认购 → 放款 → 回款、退款或损失结算 → 出资人领取。

| 目录 | 职责 |
| --- | --- |
| `src/app/` | HTTP API、认证、请求限制与服务生命周期 |
| `src/rights/` | 身份会话、角色、材料审核、签名与交易计划 |
| `src/chain/` | 网络、ABI、合约绑定与代码核验 |
| `src/ledger/` | 实例隔离的资金事实、持仓与原交易恢复 |
| `src/core/`、`src/agent/` | 确定性报价、研究分析、Demo 模拟 |
| `src/evidence/`、`src/provenance/` | 材料版本、授权下载、来源与复算 |
| `src/x402/` | 报告付款、回执核验与取回 |
| `src/ops/` | 就绪检查、单写入者租约、监控、备份与停止 |
| `web/` | 双语页面、角色工作台、钱包与融资持仓 |

Live 模式下，服务生成受限的无签名计划，当前钱包确认后才能广播。LLM 和 MCP 不能替代融资授权或直接修改已签条款。Demo 使用模拟资金流程，不会自动转换为真实融资。

## 权限与确认

管理员登记身份及角色；参与者通过钱包挑战取得短期会话。材料版本、链、实例、钱包、条款或模式变化使旧预览失效。材料发布要求当前版本审核；链上执行再次核对资格、权限和绑定。

被撤销主体仍可用原钱包取得仅退出会话，办理既有退款、领取和原资金交易恢复；此会话不恢复材料访问或新增风险权限。显示语言不属于身份：中英切换保留会话、材料和已准备的预览，只要求重新勾选该次确认。x402 报告付款不进入融资资金池。

## x402 付款取回

浏览器把原 `PAYMENT-SIGNATURE` 只留在发起付款的标签页（sessionStorage）。localStorage 中的付款记录不含签名，只有服务、付款人、条款、授权 nonce 与有效窗、未决时的原请求和交付后的报告编号。未决付款最多 10 笔，签名前检查，同一服务和钱包须先核对旧付款；已完成或过期未扣款的记录保留 30 天、最多 100 条，过期剪除，不阻止新购。重读已完成请求不收费；再次购买同一请求需明确选择“购买新快照”。

换标签页或浏览器后，付款钱包签署一次性 EIP-712 取回请求（不转移资金、不授权付款），取得 15 分钟、绑定付款人与运行代际的会话，只能列出、核对和重读该付款人的付款（`/api/x402/recovery/*`）。服务端用保存的授权走与重放相同的幂等状态机：已结算付款重新独立核验，中断的付款只读核对，未花费且已过期的授权报告为未扣款。新记录把 EIP-3009 签名以交付密钥加密保存；较早的已结算记录由已执行 `transferWithAuthorization` 的 calldata 取得签名。已结算未交付的付款只用与付款时摘要一致的原请求交付。

## 持久状态与恢复

现金事实先追加写入 JSONL，持仓及游标可以重建。账本按链、协议版本和池地址隔离，交易及日志位置去重；每个运行目录只允许一个写入进程。

未知交易保存原 nonce、calldata 与起始块，恢复只查原交易：按历史区块读取账户 nonce 并二分定位消耗它的区块（Injective 约 0.55 秒一块，不再限于其后 500 块）；节点不提供历史状态时退回 500 块内逐块扫描，再往后须填写原钱包交易哈希。确认依赖规范块；重组可撤回确认但保留历史。材料或关键历史缺失时拒绝新增风险，不将空目录当作原系统。

每笔钱包操作（认购、领取、退款）在服务端是一条 intent，状态见 `src/ledger/ledger.js`：`draft` → `broadcast_prepared`（广播前检查点，记下 nonce）→ `broadcast`（附上交易哈希）→ `confirmed`。只有 `broadcast_prepared`、`broadcast`、`reconciliation_required` 会挡住同一钱包在同一链上的下一次发送（`wallet_reconciliation_required`，`details.intent_ids` 指出是哪一条）。以下情况会让它结束而不再阻塞：

- **钱包拒绝发送**：页面调用 `POST /api/controlled/intents/:id/release`。服务端不只凭浏览器的报告：节点还知道该交易（仍在等待）时拒绝（`transaction_pending`）；保存的 nonce 已被用掉时按链上结果处理；只有 nonce 仍未使用才记为 `released`。释放后 nonce 仍被预留：同一钱包的下一次发送必须沿用它（`wallet_nonce_reserved`），所以原操作即使事后出现，两者最多只成交一笔；该 nonce 上有待打包交易时先等它打包（`wallet_nonce_pending`）。草稿记为 `abandoned`。
- **链上回滚**：回执 `status=0`、所在区块是规范块且达到确认数时记为 `reverted`，保留区块号和哈希；回执消失（重组）或重放覆盖到该区块时重新进入 `reconciliation_required`。
- **nonce 被其他交易用掉**：只有占用它的交易回执在规范链上、深度达到账本确认数时才记为 `superseded`，并保存该交易、所在区块号与区块哈希及原状态；深度不够时操作保持原状态（继续阻塞或保留 nonce），返回 `confirmation_pending`，释放路径返回 `wallet_nonce_unconfirmed`。重组使该区块失效时，账本重放把它恢复为原状态，`recoverIntent` 也会重新读链核对，而不是沿用旧结论。同 nonce、同调用的加速重发（哈希变了）改绑到实际上链的哈希。被释放的操作若最终由它自己上链，下一次发送会先返回 `released_operation_mined`，让用户核对持仓后再决定。

角色工作台的钱包交易计划（`src/rights/service.js`，登记单证、质押、放款、证明、处置等）使用同一套恢复语义：`draft` → `broadcast_prepared`（检查点）→ 附上交易哈希后 `pending`/`confirming`/`confirmed`/`reverted`。钱包拒签时页面调用 `POST /api/rights/transaction-plans/:id/release`：节点仍知道原交易或该 nonce 有待打包交易时不释放（`rights_transaction_pending`）；原交易已上链则绑定它；nonce 被其他交易占用时，只有该交易在规范链上并达到确认深度才记为 `superseded`（深度不够返回 `confirmation_pending`，重组后重新打开）；只有 nonce 仍未使用时才记为 `released`。`released` 不再阻塞同一钱包，同一份预览可直接再次确认；新计划必须沿用被预留的 nonce，所以两者最多上链一笔，被释放的操作若事后由它自己上链，下一次检查点返回 `rights_released_operation_mined`。未检查点的草稿释放后记为 `abandoned`（仍先核对链上，以防客户端跳过检查点直接发送）。会话更换或服务重启后，同一业务身份仍可核对和释放原计划。

链上事实最终说了算：任何状态的 intent 只要对上链上的现金事件就会确认。`GET /api/controlled/intents?wallet=` 列出钱包仍需处理的操作，浏览器本地记录丢失或换设备时页面据此找回。

研究上传的读取权限是独立的长期记录（`research-agent/ingest-case-access.json`，写在任务或第一次偏好之前，原子持久化），不随任务保留期、失败、重启或 Demo 重置消失；任何调用者（包括持管理员令牌的操作者）第一次为非公开案例保存偏好时都先建立这条记录。工作副本编号 `WS-…` 在写入任何东西之前就是私有的：只有能推导出它的浏览器工作区可读，其他人（含管理员令牌）也不能抢先认领别人的副本。文件损坏时 intake 拒绝启动，而不是把私有案例当成公开；访问记录加载完成之前（启动中、加载失败或缺失），除公开样例外的任何案例都按私有处理，只有管理员令牌可读，案例、任务和上传决策的读取一律拒绝（`case_access_unavailable`），偏好等其他存储即使已经加载也不例外。启动期间到达的请求先等待访问记录和偏好加载完成，再作判断。运行目录第一次启动时就写下访问记录文件和清单 `research-agent/ingest-manifest.json`（记录从何时起保存访问记录）：此后访问记录文件缺失，即使任务已全部过了保留期、或案例只保存过偏好，intake 也拒绝启动，不当作全新目录。清单也一并丢失（不完整恢复）时，保存了偏好却没有访问记录的案例按“所有者未知”处理：只有管理员令牌可读，任何工作区都不能借保存偏好认领它；从未保存过私有状态的案例不受影响。公开样例（`data/cases/` 与 Demo 案例）是只读命名空间：浏览器对样例上传或保存偏好时，落在自己的工作副本 `WS-<哈希>-<样例编号>`（`GET /api/agent/workspace/copies/:id` 返回），其他浏览器看不到，样例本身和 Agent 对公开池的约束不变；匿名请求不能写样例偏好（`public_case_read_only`，管理员令牌除外）。由上传产生的决策，任务还在时按任务所有者判断，任务过了保留期后按案例的访问记录判断，两者都没有时只有管理员可读。决策记录与它派生的 trace、锚定叶子各有保留期，清理先后不决定权限：决策记录已被清理时，`/api/agent/decisions/:id/trace` 按 trace 自己记下的案例（`attributes.case_id`，事件与执行两类 trace 都写入）鉴权，明文案例的锚定叶子（`agentbl-decision-anchor-v1`）按其 `case_id` 鉴权；记录中找不到案例的只有管理员可读。私有锚定格式（v2）只含案例哈希，作为公开证明材料返回。

上传任务的保留不取决于其他工作区的上传量：排队、处理中和待复核（含尚未被成功复核取代）的任务及其原始文件一律保留；已完成且无需复核的任务在 `AGENT_INGEST_JOB_RETENTION_DAYS`（默认 30 天）后才离开，重启时被中断的任务从中断时起算保留期。任务表（默认 500 条、每个工作区 100 条）被受保护的任务占满时，新上传明确返回 507 `intake_jobs_full` 或 413 `upload_job_quota_exceeded`，不删除任何人的待处理材料。决策证据另有自己的副本，不依赖原始上传文件。上传请求中的偏好在写任务之前校验；任务已写入但事件没有投递（例如偏好写盘失败）时，同一请求重试会补投事件。复核任务同样如此：它在创建时就记录所复核的任务和自己的事件身份（`review:<任务>`，失败或中断后重试为 `review:<任务>:attempt-N`），仍处于排队状态时重试会补投。待复核任务与纠正它的复核版本算一个逻辑任务，共占一个配额名额，所以任务表被待复核任务占满时，每个待复核任务仍能提交纠正；各版本都保留，任务表最多容纳配额的两倍。一个复核通过时，它纠正的整条链（包括更早的版本）一起进入保留期。到期任务在启动时、Agent 每次巡检和每次新上传的配额检查之前回收，被其他任务共享的内容不删除。字节额度同理：待复核任务第一次提交纠正时，可在工作区和全局字节额度之上再用一份预留（默认一批上传的上限 24 MiB），所以待复核材料占满额度时纠正仍能提交，存储总量不超过额度加预留；容量拒绝会返回已用量、上限、本工作区占用空间的待复核任务及下一步（`correct_or_withdraw_held_jobs` 或 `wait_for_retention`）。所有者也可以撤回待复核或失败的任务（`POST /api/agent/jobs/:id/withdraw`）：该任务及其各版本变为 `WITHDRAWN`，原始文件立即删除而不必等保留期，任务记录保留到保留期满，决策及其证据不受影响；撤回的记录不占逻辑配额，但计入任务表两倍配额的上限。撤回不属于新进件，运维暂停进件时仍可用。任务列表 `GET /api/agent/jobs` 分页返回（`limit`、`offset`、`next_offset`），等待纠正的任务排在最前，并给出全部匹配数 `total` 与待纠正数 `held_total`；每个任务带 `review_state`（`open` 待纠正、`superseded` 已由后续纠正接替、`resolved` 已由后续纠正解决、`withdrawn`）及最新纠正的 `reviewed_by`，页面的待办计数与运维的 `held_jobs` 用同一口径。

Agent 事件总线把接收当作提交：审计行和含该事件的索引都写成功并入队后，事件才对外可见，之后同一键才按重复处理；中途写盘失败不留下内存记录，重试会重新写入并入队，同一键的并发提交等待前一次的结果。已接收却不在任何队列中的事件（旧版本可能留下）在同键重试或 Agent 巡检时重新入队，并计入就绪检查。每个未完成事件只处于一处：排队、正由某次运行持有、或无人持有（orphaned）；无人持有的 RECEIVED 和 PROCESSING 都会被重新交出，正在运行的事件不会被重复交出。开始处理时写 PROCESSING 失败，handler 尚未执行，事件在内存中回到 RECEIVED，由巡检或同键重试原地恢复，不必等重启；完成时写盘失败，结果已经发生，监听者照常收到，未保存的状态由巡检重写。索引写失败会一直标记为未保存（`status().unsaved`），直到下一次写入成功。

原始上传先整批校验（类型、签名字节、单个与整批大小、所有权、重复资产、配额），全部通过才写入；写入时按内容哈希存一份，用 AES-256-GCM 封存（`AGENTBL_INTAKE_KEY`，未配置时在存储旁生成仅所有者可读的密钥文件）。读取时校验哈希；旧版本的明文文件仍可读，但须与记录的哈希一致。没有任何保留任务引用的文档及其文件会被删除（同一内容被另一文档引用时保留）；Demo 重置删除 Demo 任务、它们生成的案例和不再需要的原始文件，Live 记录与访问记录保留；启动时清除无记录的旧文件。每个浏览器工作区和整个存储都有容量上限，内存中只缓存最近使用的字节。一次上传按“原始文件 → 文档记录 → 任务记录”的顺序写入，任务文件是提交点：提交失败时本次请求在内存中不留任何痕迹（只保留同一工作区的访问记录），重试会重新提交而不是直接返回内存中的任务；失败时已写到磁盘、但没有任务引用的文档记录在下次启动或写入时清除。文档或任务记录写盘失败后，内存可能领先于磁盘：同一上传的幂等重试先补写再确认，Agent 巡检也会重写。

加密范围：AES-GCM 只封存原始上传文件；上传任务中的解析字段、保存的案例（`research-agent/cases/`）、偏好、文档与任务索引、访问记录和清单仍是 JSON 明文，以仅所有者可读的权限写入（类 Unix 系统上为 600；Windows 上依赖目录的访问控制），与原始文件同样属于私有运行数据，备份时一起保护，按同一保留期处理。

定价页的报价绑定案例材料的版本：每个案例按其完整内容（键排序后）计算版本摘要，报价缓存、报价有效性判断（`quoteCurrent`）都包含它。同一案例编号、模式和偏好下材料一旦变化（上传或复核产生新版本），旧报价不再有效、也不能发行；停留在当前案例时页面会跟随新版本重新报价，旧报价在新报价到达前标为“旧材料的报价”仅供参考，重算失败时仍不可发行，切走再回来得到同样的结论。

身份材料库是一个加密文件和一个写入者。链上读取不在其锁内进行：计划读取先在锁内取快照，解锁后读链，再加锁确认会话、模式代际、材料版本及计划未变后提交，否则重试或返回 `rights_plan_busy`。排队有上限（64 个、等待 15 秒，`rights_vault_busy`），放弃的请求不会延后执行；队列深度与等待时间见 rights 状态的 `vault_queue`。账本在一批新事件内增量扩展持仓投影，而不是每个事件重放全部历史。vault 每次写入都整体重新加密，因此记录有生命周期（`src/rights/retention.js`）：材料的保留期起点是创建时间 + 申报期限 + 90 天，每保存一份关联融资条款就延长到该池到期后 180 天（覆盖通知期、违约处置及其异议、迟到回款），有待对账钱包操作时不论日期一律保持可用；过了保留期先只读归档 30 天（同组织角色仍可阅读、导出证据，不能追加证据、审核或发起操作，返回 `rights_material_archived`），之后才随其证据清除。180 天前已结束的计划（未发送草稿、已确认或已回滚）会被清除；待对账计划、发布记录、已批准条款和身份始终保留。2026-10-28 前创建的证据仍按当时的材料期限过期（期限写在证据哈希内，不能事后改），需要时在材料仍可写时重新生成。

登录挑战不消耗钱包的额度：知道身份编号（或付款钱包）的人请求挑战时，得到的是同一身份、同一用途下仍有至少 2 分钟可签的那一个，只有剩余时间不足才新开，所以每个身份同时最多两个；错误签名不会用掉挑战，只有钱包本人的有效签名一次性消耗它。x402 付款取回同理，容量满时让最早的请求让位而不是拒绝所有人。钱包还可以签一次“身份查找”（不转移资金、不开启会话），列出登记在该钱包的业务身份，不必从管理员处抄写编号；查找挑战只存内存，按钱包复用。

资金池列表可按状态筛选：`open` 可认购、`active` 资金仍在池中（有托管余额，或有认购且尚未结束）、`closed` 已结束或从未有人认购；服务端在同一快照上分段向后扫描，预算用尽时提前返回并给出续读游标，读不到的池总是列出而不被筛掉。页面在列表上方汇总“与我有关”的事项（可领取、已取消可退款、待核对原交易、持有份额的池），完整目录仍在下方。

资金池列表在同一快照块上读出每个池对所有出资人都适用的认购条件（来源审查、估值有效期、估值人、单证、结算资产、进件开关），只有全部满足才标为可认购，并给出不可认购的具体原因、是否需要关闭部分募集、零认购过期池和处置进度（通知期、硬截止、复核与异议）。投资人自身的资格和条款同意在准备认购时另行核对。

研究定价与受控发行通过确定性报价连接：发行人在工作台导入条款时可选择让价格、份额和最低募集额取自铜 · 新加坡 → 上海研究案例按条款实际期限算出的报价；预览与保存之间报价变化则拒绝保存。研究案例本身不对应链上资金池，Live 下 Copilot 只解释和排序，认购在融资页对编号资金池完成。

页面刷新语义：上一页、下一页、末页沿用同一个区块快照；“获取最新数据”和“首页”读取最新区块并保留当前筛选（正在看某个池时保留该池）；只有读失败时的“重试本页（同一快照）”故意停在旧快照。概览和快照行显示区块时间及距今多久。池详情有自己的地址 `#/finance/pool/<编号>`，刷新或分享链接会打开同一个池。

出口商偏好区分草稿与已保存值：报价和 Agent 只使用服务端保存成功的值；保存失败时表单保留新值并持续标注“未保存”，提供重试和撤销，不记录“约束已更新”，也不按新值重新报价。案例切换或更新的保存会让迟到的回复失效。服务端同样只在写盘成功后才让新偏好生效（失败时读者仍看到上次持久化的值），每条偏好记录保存时的运行模式，Demo 重置只清除 Demo 偏好和不属于 Live 材料的偏好。页面上的报价绑定案例、模式代际和已保存偏好：保存成功而重新报价失败时，旧报价只作参考显示并给出“重新报价”，模拟发行不可用。Live 下偏好与上传一样带上本标签页的管理员令牌，401 时询问一次。

上传产生的私人案例（“我的工作案例”）只出现在本浏览器的定价页选择框，与公开样例分组，不进入公开目录或研究市场；上传完成后可一键切换到它，页面写明主报价对应的是公开样例还是自己的材料，刷新后回到同一案例。工作区随浏览器会话 cookie，关闭浏览器后可能无法再打开，不承诺跨设备恢复。运维监测按备份上限（256 MiB）测量运行目录，达到 80% 告警，超过后暂停新进件；上传存储上限因此不超过备份上限的一半。

资金池和持仓按固定区块及哈希分页。RPC 采用有界并发、排队、超时和幂等读取重试；不完整读取返回明确失败，未知金额不显示为零。超时底层请求在实际结束前继续占槽，避免积累无限后台调用。实例激活后没有升级、改绑、转移所有权或自毁路径，所以只读页面复用 5 分钟内的完整核验，每次请求只重读网络和 Hub 登记；签名、交易与回执路径仍完整核验。资金池分页在链上存在规范 Multicall3（运行时代码哈希与以太坊主网一致）时用两次批量调用读取一页，否则逐项读取。

## 当前实例与信任边界

当前公开配置是 control version 3、Rights v3 签名域。旧 v1、v2 使用各自冻结的 ABI/runtime，只保留应用内查询与既有退出；不能用新 ABI 解释旧条款。共享治理与 Hub 保留旧资产占用，新 Registry、Pool、Controller 和资金账本独立。

完整条款可下载并离线复算，前端也独立核对签名域和承诺。当前实例全部已发行池的公开条款随仓库发布在 `data/disclosures/`，新 checkout 无需 vault 即可阅读。已批准的条款包另按披露哈希保存公开副本（运行目录 `rights/public-disclosures/`，可复制到 `data/disclosures/` 随仓库发布）。公开读取先找公开副本，所以 vault 缺失、密钥配错或密文损坏都不会挡住已发布的条款；副本必须重算出相同哈希，否则不被采用（私有材料读写对损坏数据仍一律拒绝）。

条款读取分两层：历史层核对这份条款就是该池在链上承诺的那份（链、控制器、池、termsHash、逐字段一致），不符即失败；当前层核对持有人、治理、估值人、六个签约角色和链上发行价格份额是否仍与签署时一致。只读查看和下载（`GET /api/controlled/offerings/:id/terms`）只要求历史层，结果的 `current` 写明当前是否还能据此新增操作及原因（如 `valuer_revoked`、`offering_changed`、`legacy_exit_only`），旧版本实例的条款同样可读；同意条款、认购及其广播前复核仍要求两层都通过，否则返回 `financing_terms_changed` 和原因。合约可以约束登记域内对象和测试代币，无法独立证明货物、单证、估值或法律权利真实。研究角色由同一操作员保管，不代表独立组织。

页面以融资和退出为默认入口，角色待办、池详情、完整条款及持仓可达；研究案例、定价、Agent 等保留独立导航。窄屏布局与自动化钱包回归属于已有测试，人工钱包验收结果见 [acceptance.md](acceptance.md)。
