# 人工验收

这是当前交付唯一保留的待办，状态为 **PENDING**。一位未参与开发的人应实际操作测试钱包并核对余额，发现的问题修复后复测。自动签名、脚本回执和示例记录不能代填通过。

## 准备

- 使用当前受控 v2 实例、虚构单据和 TEST_USDC；记录完整提交、chain ID、合约地址及验收日期。
- 验收者使用自己实际操作的测试钱包。组织身份由管理员登记，业务权限与链上角色对应；私钥不写入验收记录。
- 建立新的、尚未到截止且已审核的研究池。已经结清的历史样例只供只读参照，不重复执行原交易。
- 记录桌面操作系统、浏览器和钱包版本。真实手机不在此次验收范围。

## 操作

1. 连接钱包，核对网络、实例和身份。阅读完整条款并核算本金、价格、份额、目标回款、截止、费用及收款方。
2. 在一次确认中主动拒签，确认资金未动、没有伪造的成功回执；切换钱包后旧预览应失效。
3. 按角色待办完成材料交接、审核、holder 同意和发行。由两位测试出资方分别认购，融资主体收款并实际回款，出资方各自领取。
4. 在另一个失败募集池上等待真实截止后退款，核对原成本、份额及池内 escrow。
5. 演示损失结算、份额销毁后的迟到回款，以及刷新或断网后的原交易恢复；未知结果只查原交易，不再付一次款。损失路径可先观察已结清的真实测试网交易；若宣称亲自操作了某一步，必须保存该步实际签名与交易。
6. 验收者用自己的话说明谁负责单证、链上保证什么、测试资产与真实业务的区别，记录无法理解或无法完成的步骤。

## 通过与记录

每一步记录实际操作者、签名或拒签结果、原交易 hash、规范块、前后余额原子整数、查询来源、失败和重试。使用区块浏览器或独立 RPC 核对到账，不能只相信页面的“成功”。

正常兑付和退款须由验收者实际完成；损失与未知交易恢复须有可复核的演示记录。金额不一致、权限越界或可能重复付款时停止后续新增操作，保存证据并修复。

记录保存为本地验收产物，不包含私钥、会话 token 或私有单证。所有必需步骤有实际记录且受阻问题已处理后，才将本文件状态改为 VERIFIED 并注明对应提交和记录位置。

真实手机、独立物理主机、签名权接管及商用准入已取消，均不作为本次人工验收的通过条件，也不因取消而视为通过。
