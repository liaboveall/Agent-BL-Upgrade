## 已落地的改动

| 评估项 | 当前行为与回归证据 | 部署边界 |
|---|---|---|
| F01 最终定价 | 在价格钳制、向上取四位价格、抵押缩量和整数供给之后，检查实际利润分成、净利润、年化和融资缺口。低利润、零利润和亏损均不能被警告放行。保留负利润原值，区分申报利润与缺成本时的 12% 假设；见 `reviewRemediation.test.js` | 应用源码修复 |
| F02 生命周期 | 调价只改变未售份额单价与报价版本，保留 Open / Subscribed / Funded / InTransit；暂停后恢复原阶段。合约、Demo executor、模拟器与测试同步。四种阶段分别遍历价格动作和后续认购/发运；见 Hardhat 同名回归 | 新合约为本地 v3 候选；旧部署未变 |
| F03 资产唯一性 | 新身份 `title-v2` 使用规范化签发主体与原始提单身份，内部 case ID、货物显示名称和单证修订不能创造第二项资产。同文档跨案件和已保存同提单另建案件会被拒绝。pool #2/#3 的旧哈希显式保留，改名案件仍回到旧关联 | 新开盘要求合约 `protocolVersion >= 3`；旧版仅允许关联既有资产，须先完成人工审查的身份迁移 |
| F04 欠款与解押 | `settle` 要求实收覆盖已认购份额的原始目标债务；不足不解押。候选合约提供追加回收、锁定到期日、逾期 Defaulted、owner 明确损失结清 LossSettled 与损失金额。registry owner 无法越过融资池直接解押。应用与 CLI 另核验约定付款方、收款方、金额、资产及规范回执 | 候选仍只记录证据，不托管和兑付稳定币；新增 default/loss 方法不接入 Agent 自动执行 |
| F05 上传隐私 | 公共目录仅有策划样本；上传留在私有工作区。不可猜的 HttpOnly 工作区 cookie 的哈希绑定作业，文件索引隔离工作区；任务、决策、追踪、审批、偏好、SSE、持仓、市场及 MCP 按可见性过滤。无原工作区的旧上传只供管理员核对 | 这是单进程原型的工作区能力隔离，不能替代企业身份、租户组织权限或生产发布审批 |
| F06 执行模式 | Demo 铸造只模拟，连着钱包也不发送。LIVE 的独立 AgentBLRWA 实验先展示网络、合约、案件、价格与融资额，再请求明确确认；失败保持失败。产品说明与受控协议发行区分 | 浏览器验证使用钱包桩，未做真实钱包交易 |
| F07 报价串用 | 切换时原子清除报价、结果与融资额并进入加载态；请求版本和 mode generation 拒绝乱序响应。选中报价须匹配 case ID；签名前再校验报价、案件、世代、模式、钱包和网络 | 含延迟 B、快速 A→B→A 的真实浏览器回归 |
| F08 偏好串用 | 每案件独立偏好，缺省为空；报价缓存绑定案件偏好和运行世代。加载失败暂停操作，旧请求不能清除新请求的 busy 或替换其结果 | HTTP/浏览器回归 |
| F09 可认购性 | 服务端共享规则返回 `can_subscribe`、剩余额度、禁用原因；市场按钮/状态/统计和 Copilot 使用同一准入。Funded、InTransit、满额及未知阶段均关闭 | Demo 与本地规则已验证 |
| F10 数据质量 | null / 空白 / 布尔 / 非数值不能变成零。波高保留与日期配对，价格要求正数及实际观测时间。缓存取回与底层观测分开；旧行情标 stale，缺关键来源要求 review，不能推进 Live 风险恢复或自动动作 | 行情允许 72h 周末窗口，PortWatch 72h 发布宽限，预报 1h；尚未接交易所完整节假日日历和商业数据 SLA |
| F11 风险恢复 | 同 source / event identity 的新观测可降级或显式 resolved；旧版本不能覆盖新版本，历史另存。空列表和失效来源不会清除旧风险，不同来源共存；tracker 对降级也发变化事件 | 持续监管校准和真实人工接管仍需业务验收 |

补充修复：认购使用整数份额及六位小数金额，记录实际金额、未用预算、原始价格/目标与报价哈希；重定价不改已买份额。主界面保留四位价格，解释“市场条款/当前试算”的区别，使用结构化风险类型，避免把无风险信号误判为单证问题。主题文字和深色日志的对比度已调整，中英文主解释均本地化。

公共 Demo 场景只能由服务端读取仓库里的虚构样本，以内部 `source=scenario` 标为 `public-demo`；上传请求不能自行指定发布状态。真实上传没有自动公开通道。`GET /api/agent/workspace/cases` 是私有工作底稿入口，不能作为公开发行摘要。

## 测试网迁移审阅方案

本地候选修改了 `EBLRegistry` 和 `RWAOfferingPool`。它们不是代理合约，修改源码不能修复已经部署的地址。现有 `public/chain-config.json`、旧部署回执和 pool #2/#3 均保留。新状态附加在旧枚举之后，`Repaid=9`、`Cancelled=12` 等旧编码没有变化。

1. 只读盘点全部旧 eBL、提单签发主体/原始标识、历史修订、抵押和 pool，生成 v1→v2 关联清单；冲突必须人工解决。不能仅凭新哈希 `isUnique=true` 重铸旧抵押。
2. 核实旧池订阅份额、原始目标债务、付款/到港证明及角色权限。历史资金与凭证逐条保留；不能用新池覆盖旧投资记录。旧版有认购者或已进入运输/满额阶段时，应用拒绝 REPRICE。
3. 评审候选版本、最终字节码、网络、初始化参数、默认到期日/每池到期日、权限与测试清单，再由用户逐笔批准独立部署和初始化。既有 D8 的不重新部署承诺没有被本次代码整改自动转成广播授权。
4. 只有新部署回执与字节码、角色和恢复流程通过只读复核后，才更新目标地址和公开 ABI。新开盘仍逐步审批、静态预检、签名和核验。
5. 迁移涉及历史持仓、资金、货权或解押时另列每笔动作的具体影响。上线前补真实 USDC 托管、放款、退款、claim/redeem、部分损失分配、来源权限与独立恢复；当前候选不能用于承接真实资金。
