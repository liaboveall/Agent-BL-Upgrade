# W5 尝试、失败与修复记录

失败文件和收据保留，不以后续通过输出覆盖。目录使用新加坡批次日期 2026-10-18，实际时间以每份 UTC receipt 为准。

- 初次 Docker Desktop 未提供 engine API，主机日志显示 secrets-engine socket 启动失败。重启已失败的 Desktop / backend 进程后恢复，未重置设置或 volumes。实际镜像另行构建并验证非 root、只读根、cap-drop 及健康。
- 最早 W5 业务材料测试使用了错误的 `summary` 字段，并把对象形式的 synthetic verifier 当成函数；集成脚手架也曾错误调用 HTTP helper 导致 URL 为 undefined。相应初始日志保留，改用正式接口和实际 EVM 后重新测试。
- 实际跨层测试发现：控制器包装放款被资金 rebuilder 当作直接 pool 调用解析，导致到账后持仓对账失败。现从规范回执中的实际 ERC-20 Transfer 核对资金去向，兼容控制器 / 治理包装。新增 REFUND 意图的精确事件匹配，回归覆盖实际认购、违约后两笔回款、领取和失败募集退款。
- 首次干净构建将 solc immutable 引用的 AST 编号当作 artifact 语义，导致相同字节码误报差异。仅按相同 start / length 归一化编号；ABI、creation / runtime 字节仍逐字比较，没有忽略 metadata 或业务代码。
- 干净构建随后发现真实的旧 AgentDecisionLog artifact 残留：其 build-info 使用 OpenZeppelin 5.6.1 remapping，而当前锁文件为 5.1.0。旧产物保留于 `agent-log-artifact-before-clean.json`；全量 force rebuild 后新审计实例使用固定最终产物。旧链上实例保持历史部署身份。
- Git checkout 的换行策略会改变原始单证样本哈希。技术源和构建元数据固定 LF；供应商资源、历史证据与原始单证样本保持捕获字节。相关 normalization receipt 保留。
- 第一轮连续检查在 600 秒内只有 596 个实际观察点，被判失败。改为在保留时长目标的同时完成至少 600 点，并保留有界超时；没有降低观察次数或错误率门槛。
- 一轮后续检查完成 600 点但出现 1 次未就绪，仍记 FAIL。当时未保存该瞬间的具体 check，不能重造原因；其计数和服务日志保留。后续版本增加失败观测和原始 ops-alerts 留存，再以最终源码和隔离运行复验。另一轮已观察到 600 点 / 0 失败，但若源码在整套检查期间变化，仍不作为最终版本放行。
- 多次工程收敛期间的 rehearsal 跨过源码 / 构建配置修改，收据明确 `source_unchanged=false`；即使命令通过，也不能冒充最终同版本验收。最终结果只取冻结后完整运行及相应 CI。
- 部署 CLI 增加 durable journal、签名哈希双副本核对、缺失历史 / 密钥拒绝重新初始化和研究角色地址核对。未知广播只读核验原哈希，不重新签署同一步。新增失去 journal / 记录冲突回归。
- 首次真实审计锚定已经部署并登记版本，但完整材料归档失败：Zod 的 `text.max(500000)` 仍保留通用 `text` 的 1,000 字符校验。修复为独立的 500,000 字符材料 schema，增加超过 1,000 字符的完整包可复算及超限拒绝回归。原版本登记和交易继续保留，最终修复后的 source hash 另行登记并锚定；此次期间的完整验收运行不算最终冻结版本。
- 修复后真实锚定首次运行只处理了历史旧版本 batch，因新版本尚未进入下一 batch 而拒绝放行。再次运行只核对原交易并处理新 batch，最终新版本包含证明通过；没有丢弃旧记录。直接调用 validator 也曾被其 npm 入口要求拒绝，随后使用正式 npm 命令。
- 冻结源码 `8a9d1ad8...` 的完整运行 16 项命令通过，唯一失败是新增的证据 runner 中数组绑定 `prefer-const` 警告（不属于产品源码清单）。改为 const 后单独重新执行全仓 lint；原失败收据保留，最终汇总明确使用补充 lint 收据，不改写原完整运行的 `passed=false`。
- 暂存区逐文件核对发现 8 份旧单证虽已有 `-text` 属性，Git stat 缓存仍复用了历史 LF blob；工作树原始文件为 CRLF。对 `data/uploads` 执行显式 `git add --renormalize` 后，索引按原始字节保存。源码工作树摘要没有变化，原始失败核对报告保留，最终索引再次逐字核对。
- 实际容器停止出现一次 exit 137，备份拒绝其跨主机残留租约，没有自动抢锁。核对容器 ID / hostname、退出状态和无其他挂载写入者后，显式退役旧租约并保留原 owner 记录，材料再次解密核验。随后重启 / 正常停止复验为 exit 0，租约自动释放；运营停止命令使用 `docker stop -t 30`。
- 独立恢复准备首次被 GitHub HTTP 422 拒绝：50,000 字符加密分片超过该服务限制。原尝试和停止租约记录保留在 `release-supplements/`；仅发布恢复脚本改为 40,000 字符，并容忍未创建变量的清理 404。应用 / 合约 / UI 未变化，重新执行 lint、check、干净构建和当前版本锚定；正式同 SHA CI 继续完整回归。没有把旧源码完整运行改写为新发布脚本已经运行。
